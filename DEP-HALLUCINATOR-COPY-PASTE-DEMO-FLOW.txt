PHASE 3 — DEMONSTRATE MODIFICATION 2 IN REAL USE
=================================================

MODIFICATION 2 SUMMARY TO EXPLAIN:
The scanner accepts Maven pom.xml files from users, so XML must be treated as untrusted.
A malicious XML external entity can try to expand local file contents. This is called an
XXE attack. Modification 2 uses defusedxml to reject dangerous XML features while keeping
normal Maven dependency parsing unchanged.

EXPLAIN:

the production dependency in pyproject.toml.

EXPECTED IMPORTANT TEXT:

from defusedxml.common import DefusedXmlException
defusedxml>=0.7.1

PHASE 5 — SHOW THE SCANNER'S POWER ON THREE REPOS
===================================================

PERCENTAGE EXPLANATION TO PRESENT:
Dep-Hallucinator provides a risk level for each dependency, not one official repository
safety percentage. For an easy classroom comparison, this demonstration uses:

safe percentage = LOW findings / total findings x 100

Only LOW is counted as safe. MEDIUM, HIGH, CRITICAL, and ERROR all require review.
This percentage is a summary, not a guarantee that a project has no security problems.

TROUBLESHOOTING BEFORE STARTING
===============================

If Step 7 says the container name already exists, inspect it:

docker ps -a --filter name=dep-hallucinator-evidence-20261008

If it is the old disposable demonstration container, remove it:

docker rm -f dep-hallucinator-evidence-20261008

Then repeat Step 7.

If Docker is not responding:

open -a Docker

Wait until Docker Desktop is ready, then repeat Step 6.

If /samples does not exist inside Docker, check the host folder:

ls -la ~/Downloads/Dep-Hallucinator-Test-Repositories

If it is missing, extract:

~/Downloads/Dep-Hallucinator-Test-Repositories.zip

If a registry scan reports ERROR, check internet access and retry. ERROR means the
registry could not be checked; it must not be counted as safe.
