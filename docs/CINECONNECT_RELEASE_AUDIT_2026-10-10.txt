F. REMAINING PROBLEMS

Critical launch blockers
1. Live APP_ENV is development and both authentication secrets fail the project's
   production length requirements. Production hardening remains. Secret rotation
   must preserve field encryption: legacy encrypted values may derive their key
   from SECRET_KEY. Do not blindly change it or delete stored financial data.
2. Live PAYMENT_MODE is sandbox. Decide/configure the legitimate production
   payment workflow: existing manual bank-transfer verification or an actual
   merchant gateway integration. No fake gateway may be labeled live.
3. Configure actual SMTP sender credentials and verify delivery and recovery
   end-to-end. Provide credentials securely in server environment configuration,
   not chat. SMS/push provider delivery, where promised, remains unverified.
4. Android release configuration still uses com.example.cineconnect and debug
   signing. The generated APK is for QA, not a Play Store release. Need the
   product's registered identifier and authorized release signing configuration.
5. Xcode 26.4.1 and the iOS 26.4 SDK are present, but no iOS Simulator runtime is
   installed. The project also has no Apple Developer team, signing identity,
   provisioning profile or export configuration, and still uses an example bundle
   identifier. A simulator/device/App Store release cannot honestly be certified.
6. Full screen-by-screen interaction audit and authenticated production UAT across
   every role remain incomplete. Do not declare every button/calendar verified.

Important non-blocking / scope-dependent items
- No configured Sentry DSN was found. Structured logs exist, but operational
  alerting, retention and restore-tested offsite backups need verification.
- Per-device logout currently revokes refresh sessions; unlike password reset,
  immediate invalidation of an already issued access token for individual-device
  logout is not separately certified.
- AI outputs/retries, large uploads, notifications, payment disputes and actual
  external legal/insurance/distribution flows need provider-backed tests.
- Further compactness and screen-by-screen visual refinement across all portals
  remain; this is not a claim of the entire sixteen-phase transformation finishing.
- Physical mobile performance, assistive-technology audit and browser compatibility
  beyond the tested Chrome views remain.

Optional enhancements
- Wasm-compatible secure storage; further media caching and measured bundle budgets.
- More nuanced contextual cursor states without sacrificing native interaction.
- Configurable project planning checklists rather than one shared saved-field list.
