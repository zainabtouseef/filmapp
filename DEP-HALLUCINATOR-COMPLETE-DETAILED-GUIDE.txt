HOW TO UNDERSTAND TERMINAL RESULTS
----------------------------------

Exit code 0 means the command completed successfully.
Exit code 1 normally means a failure, but the scanner deliberately returns 1 when it
finds a CRITICAL package. Therefore, exit code 1 is EXPECTED for the mixed and fake-name
sample repositories.

Pytest output such as "2 passed" or "63 passed" means every selected test succeeded.
Warnings are not failures. This project currently produces 37 pre-existing asynchronous
mock warnings during the full suite.

PART D — INSPECT AND TEST MODIFICATION 2
========================================

MODIFICATION 2 IN EASY WORDS:
Maven pom.xml files are untrusted input. A malicious XML file may define an external
entity that tries to read a local file. Modification 2 replaces the ordinary XML parser
with defusedxml, which blocks dangerous XML features before dependency extraction.

This attack class is called XML External Entity injection, usually shortened to XXE.

FILES AND LOCATIONS:
src/dep_hallucinator/parsers.py lines 8–10: # modification2 and safe imports
parsers.py lines 780–833: secure parsing and unsafe-input error handling
pyproject.toml line 35: defusedxml>=0.7.1
tests/test_parser_security.py lines 6–25: the malicious XML rejection test

PART F — SCAN THE PROVIDED SAMPLE REPOSITORIES
==============================================

IMPORTANT:
These folders contain only requirements.txt files. Scanning reads package names; it does
not run pip install and does not install the fake demonstration packages.

Dep-Hallucinator reports LOW, MEDIUM, HIGH, CRITICAL, or ERROR for each dependency.

For a simple classroom comparison, this guide calculates:

safe percentage = LOW findings / total findings × 100

Only LOW is counted as safe. ERROR means unknown and must not be counted as safe.
This percentage is a summary of the scanner result, not a guarantee that a project has
no vulnerabilities or malicious code.

TROUBLESHOOTING
===============

PROBLEM: Docker says the container name already exists.

INSPECT IT:
docker ps -a --filter name=dep-hallucinator-evidence-20261008

IF IT IS THE OLD DISPOSABLE TEST CONTAINER, REMOVE IT:
docker rm -f dep-hallucinator-evidence-20261008

THEN REPEAT STEP 6.


PROBLEM: Docker cannot connect to the daemon.

COMMAND:
open -a Docker

Wait until Docker Desktop is ready, then repeat Step 5.


PROBLEM: The /samples mount source does not exist.

Check:
ls -la ~/Downloads/Dep-Hallucinator-Test-Repositories

If needed, double-click this ZIP in Finder:
~/Downloads/Dep-Hallucinator-Test-Repositories.zip


PROBLEM: Registry scans show ERROR instead of LOW or CRITICAL.

MEANING:
The scanner could not reach PyPI. ERROR is unknown, not safe.

FIX:
Check internet access and repeat the scan. The automated modification tests do not need
live PyPI and can still be run while offline.


PROBLEM: A mixed or fake-name scan returns exit code 1.

MEANING:
This is expected. The sample intentionally contains CRITICAL dependencies. The scanner
is correctly reporting risk.


PROBLEM: Pytest prints 37 warnings.

MEANING:
Warnings are not failures. Confirm the last line still says:
63 passed, 37 warnings
